## Overview

This project demonstrates Firebase Cloud Messaging (FCM) integration in
a Flutter application. The app receives cloud messages, processes custom
data payloads, updates the UI, and handles notification interactions
across different application lifecycle states.

The implementation supports:

- Foreground message handling with `FirebaseMessaging.onMessage`
- Background notification taps with
  `FirebaseMessaging.onMessageOpenedApp`
- Cold-start notification handling with `getInitialMessage()`
- Background message handling
- Notification permission requests
- FCM registration token retrieval and refresh handling
- Custom payload validation
- Dynamic UI updates based on message data
- Safe rejection of invalid payloads without crashing or replacing valid
  content

### Main Files

- `lib/main.dart` — Initializes Firebase, registers the background
  handler, displays the Activity 14 UI, validates message data, and
  updates the interface.
- `lib/fcm_service.dart` — Centralizes FCM permission handling,
  foreground messages, notification taps, initial messages, token
  retrieval, and token refresh handling.
- `lib/firebase_options.dart` — Generated by FlutterFire CLI for the
  configured Firebase project.

## FCM Lifecycle Handling

| App State                     | Handler                                          |
|-------------------------------|--------------------------------------------------|
| Foreground                    | `FirebaseMessaging.onMessage`                    |
| Background + notification tap | `FirebaseMessaging.onMessageOpenedApp`           |
| Cold start + notification tap | `FirebaseMessaging.instance.getInitialMessage()` |
| Background processing         | `FirebaseMessaging.onBackgroundMessage()`        |

## Valid Test Payload

``` json
{
  "notification": {
    "title": "New promotion",
    "body": "Switch the screen to the promo asset"
  },
  "data": {
    "asset": "promo",
    "action": "update_ui"
  }
}
```

The accepted asset values are `default` and `promo`. A valid UI update
requires `action=update_ui`.

## Invalid Payload Safeguard

Example invalid data:

``` json
{
  "data": {
    "asset": "unknown",
    "action": "update_ui"
  }
}
```

The app rejects unsupported payloads, displays a diagnostic message,
preserves the previous valid content, and continues running without a
crash.
